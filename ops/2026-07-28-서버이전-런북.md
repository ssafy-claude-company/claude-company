# 서버 이전 런북 — VPS(<OLD_SERVER_IP>) → 미니PC(murmur.dojin-mini.shop)

> **읽는 주체**: 새 서버(미니PC)의 세션. **이 이전은 새 서버가 리드한다** — 구 서버는 집 서버 안으로 들어올 수 없다(SSH 22 차단). 그러므로 **전부 "끌어오기(pull)"** 로 진행한다.
> **사용자 확정**: 새 서버의 현재 DB는 **덮어쓴다**(구 서버 데이터가 진짜 — 실사용 회원·결제 기록).

## 0. 출발지 정보
- 구 서버: `root@<OLD_SERVER_IP>` (도메인 `murmur-ai.duckdns.org`)
- SSH: **22번** 정상. (22가 막힌 망이면 **80번**도 열려 있다 — `ssh -p 80`, sslh 다중화)
- 구 서버 상태: 모든 레포 미커밋 0, HEAD `f626423`. murmur는 GitHub에 푸시 완료.

## 1. 열쇠 교환 (가장 먼저)
새 서버에서 키를 만들고 **공개키를 사용자에게 전달** → 사용자가 구 서버 담당 세션에 주면 등록된다.
```bash
ssh-keygen -t ed25519 -C "minipc-migration" -f ~/.ssh/id_ed25519_migrate -N ""
cat ~/.ssh/id_ed25519_migrate.pub          # ← 이 한 줄을 사용자에게
```
등록 후 확인:
```bash
ssh -i ~/.ssh/id_ed25519_migrate root@<OLD_SERVER_IP> "hostname; uptime"
```

## 2. 새 서버 현황 파악 (덮어쓰기 전 필수)
```bash
ls -la /root/                                   # 기존 체크아웃 위치 확인
systemctl list-units --type=service --state=running | grep -iE "murmur|organt|nginx|postgres"
sudo -u postgres psql -tAc "\l"                 # DB 존재·이름
python3 --version; psql --version               # 구 서버=Python 3.12.3 / PostgreSQL 16
```
**구 서버와 경로가 다르면 맞춰라** — 서비스 유닛·`PYTHONPATH`가 절대경로(`/root/ClaudeCompany`)에 의존한다.

## 3. 서비스 정지 (분기 방지)
**양쪽에서 러너가 동시에 돌면 봇이 두 DB에 따로 기록해 데이터가 갈라진다.** 복사 직전에:
```bash
# 새 서버에서
systemctl stop organt-runner murmur-web 2>/dev/null
# 구 서버에서 (사용자 승인 후 — 원격 실행)
ssh root@<OLD_SERVER_IP> "systemctl stop organt-runner"
```
구 서버 웹은 검증이 끝날 때까지 살려둬도 된다(읽기 전용 참고용). 단 **러너는 반드시 정지**.

## 4. 코드 가져오기
```bash
# 4-1. murmur는 GitHub이 정본(푸시 완료) — 새로 받거나 pull
git -C /root/ClaudeCompany/murmur pull origin main   # 이미 있으면
# 없으면: git clone https://github.com/ssafy-claude-company/murmur.git

# 4-2. 나머지는 GitHub 백업이 없다 → 복사가 유일 수단
rsync -avz --delete \
  --exclude '.venv' --exclude 'node_modules' --exclude 'ops/var' \
  -e "ssh -i ~/.ssh/id_ed25519_migrate" \
  root@<OLD_SERVER_IP>:/root/ClaudeCompany/ /root/ClaudeCompany/
```
> `system`·`organt`·`guide`·루트(`ops`)는 **원격 저장소가 없다.** 이 복사가 유일본 전달이다 —
> 성공을 검증하기 전까지 구 서버를 지우면 안 된다.

## 5. 설정·비밀 (git에 없음 — 반드시 수동)
```bash
S="ssh -i ~/.ssh/id_ed25519_migrate root@<OLD_SERVER_IP>"
$S "cat /etc/murmur-web.env"            > /etc/murmur-web.env
$S "cat /root/ClaudeCompany/.dburl"     > /root/ClaudeCompany/.dburl
chmod 600 /etc/murmur-web.env /root/ClaudeCompany/.dburl
```
**`/etc/murmur-web.env` 안의 `DATABASE_URL`·`ORGANT_GUIDE_TOKEN`은 새 서버 값에 맞게 조정**하라
(DB 접속 정보가 다르면 웹이 안 뜬다). 토큰은 웹과 러너가 **같은 값**이어야 한다.

## 6. 봇 자격증명 ★ 없으면 AI 직원 전원 정지
```bash
rsync -avz -e "ssh -i ~/.ssh/id_ed25519_migrate" \
  root@<OLD_SERVER_IP>:/root/.claude/.credentials.json \
  root@<OLD_SERVER_IP>:/root/.claude.json  /root/.claude/
chmod 600 /root/.claude/.credentials.json
```
> `/root/.claude` 전체는 2.9GB(대부분 대화 기록)라 통째 복사는 불필요. 위 2개가 핵심이다.
> 복사 후에도 인증이 안 되면 새 서버에서 `claude` CLI로 **재로그인**하면 된다.

## 7. DB 이전 (33MB) — 새 서버 DB를 덮어씀
```bash
ssh -i ~/.ssh/id_ed25519_migrate root@<OLD_SERVER_IP> \
  "sudo -u postgres pg_dump -Fc murmur" > /tmp/murmur.dump
sudo -u postgres dropdb --if-exists murmur
sudo -u postgres createdb murmur
sudo -u postgres pg_restore -d murmur /tmp/murmur.dump
# 확인
sudo -u postgres psql murmur -tAc "SELECT count(*) FROM sns_person;"
sudo -u postgres psql murmur -tAc "SELECT count(*) FROM sns_payment;"
```

## 8. 봇 기억·산출물 (1.4GB)
```bash
rsync -avz -e "ssh -i ~/.ssh/id_ed25519_migrate" \
  root@<OLD_SERVER_IP>:/root/ClaudeCompany/ops/var/ /root/ClaudeCompany/ops/var/
```
> 안 옮기면 진행 중 프로젝트 산출물과 봇 세션 기억이 사라진다(봇이 기억상실 상태로 재시작).

## 9. 실행 환경
```bash
cd /root/ClaudeCompany
python3 -m venv .venv && .venv/bin/pip install -r murmur/backend/requirements.txt
cd murmur/frontend && npm ci && npm run build      # 프론트 산출물
```
`PYTHONPATH=/root/ClaudeCompany` 로 `from system.X` 가 풀린다(패키징 없음).

## 10. 서비스 등록
구 서버 유닛을 참고해 새 서버에 맞게 조정(경로·venv 위치 확인):
```bash
$S "cat /etc/systemd/system/murmur-web.service"     # gunicorn
$S "cat /etc/systemd/system/organt-runner.service"  # 러너(--remote http://127.0.0.1:8000)
systemctl daemon-reload && systemctl enable --now murmur-web organt-runner
```
- **nginx**: 새 서버에 이미 `murmur.dojin-mini.shop`으로 동작 중 → `server_name`만 새 도메인 유지.
- **보안 규칙 반드시 이식**: `location /api/guide/ { deny all; }`, `/api/atelier/ { deny all; }` — 러너만 localhost 직결로 쓴다.
- **sslh(80번 SSH 다중화)는 이전 불필요** — 구 서버에서 사무실 망 차단을 우회하려던 임시 조치였다.
- `atelier`, `ttyd`(웹 터미널), `organt-app-*`(봇이 만든 앱 2개)는 **필요할 때만** 이식.

## 11. 검증 (이 순서로 전부 통과해야 이전 완료)

추가로: 로그인 → 채널 목록 → 결제 내역이 **구 서버와 같은 데이터**로 보이는지 눈으로 확인.

## 12. 마무리
- 검증 통과 전까지 **구 서버 삭제 금지**(원격 백업 없는 레포 3개 + ops 때문).
- 구 서버 러너는 정지 상태 유지(재가동하면 데이터 분기).
- 도메인: 새 주소는 이미 동작 중. 구 주소(`murmur-ai.duckdns.org`)를 계속 쓸지는 사용자 결정.
- 이전 완료 후 `ops/STATE.md`에 라이브 위치 변경을 반영하라(정본이 구 서버를 가리킨 채면 다음 세션이 오도된다).

## 13. 함정 (구 서버에서 실측된 것)
- **이중 스택**: 구 서버는 `/root/ClaudeCompany`(작업)와 `/root/murmur-stack`(라이브 웹)이 별도 체크아웃이었다(같은 커밋 유지). 새 서버는 **한 곳으로 단일화**하는 편이 낫다 — 불일치 사고가 줄어든다.
- **워커 CLI**: `/opt/node22/bin/claude`가 구 서버엔 없어 SDK 번들 CLI로 폴백 중이다. 새 서버도 동일하면 그대로 두면 된다.
- `/root/wt/*`(세션 worktree)는 **복사 불필요** — 잔여는 브랜치에 보존돼 있다.
